# M1 接管卡｜一笔收货怎么进库存

1. **业务**：采购欠量按已收算，但仓库能不能发货取决于是否上架。收 8 不等于可拣 8。
2. **入口**：[采购页](../../../frontend/src/views/Purchase.vue)和[收货页](../../../frontend/src/views/Receipt.vue)分别提交数量；服务端由 [`InboundCommands.receive()` / `putAway()`](../../../backend/src/main/java/com/homefulfillment/inbound/InboundCommands.java) 返回实际业务号，用 [同号 SQL](../../../infra/mysql/verify-m1.sql) 对账。
3. **别改坏**：PO 和 SKU 锁之后仍要做条件更新；幂等凭证、单据、库存账和审计同事务。上架 `−q/+q` 是双边转移，不能当第二次入库。

| 改什么 | 从哪里开始 |
|---|---|
| 加一个只读采购列 | `InboundRead` 的查询和响应 record，再到 `views/inbound.ts` 与 `Purchase.vue`；不用改收货命令。 |
| 定位一次超收为什么没入库 | 找 `InboundMapper.incrementReceived()` 的 `WHERE`，再看 `InboundCommands.receive()` 的执行顺序和 A03。 |
| 定位移出后移入失败 | 看 `InventoryLedger.moveToPickable()` 与 `CommandJournal` 事务边界；确认没在方法内吞异常。 |
| 修改表单提示或页面排版 | 找具体 `views/*.vue`；仅跨页统一样式改 `workbench.css`。别用文案或隐藏按钮代替后端校验。 |

MyBatis 把条件写入集中在两个 Mapper；查询直接用 JdbcClient，不额外叠通用仓储框架。Spring Security 管会话和 CSRF，域授权由 `Identity.Actor` 检查。真实 MySQL 回归入口：[`tests/m1.py`](../../../tests/m1.py)。改事务或权限前先复跑 A03/A04；用户接管程度只记在 [学习方案](../../../docs/learning.md)。

指纹由业务字段和规范化路径按键排序的 JSON 生成，不受客户端 JSON 字段顺序影响。测试包括两个客户端用同一键并发提交、撤销仓权限后重放，以及服务端已写入但浏览器丢响应后刷新重试。依赖只补安全版本，不为 M1 引入 Redis 或 MQ。

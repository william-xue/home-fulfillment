# M3 接管卡｜拣货不扣账，出库与签收分开

1. 仓管按库位确认任务，账仍有现存和预占；全部任务完成后确认发货，才扣两者。承运轨迹不是库存动作。
2. [`FulfillmentDetail.vue`](../../../frontend/src/views/FulfillmentDetail.vue) → [`OutboundCommands`](../../../backend/src/main/java/com/homefulfillment/fulfillment/OutboundCommands.java) → [`Fulfillments`](../../../backend/src/main/java/com/homefulfillment/wms/Fulfillments.java) 与 [`InventoryLedger.consume()`](../../../backend/src/main/java/com/homefulfillment/inventory/InventoryLedger.java) → 配对的 `dispatch` 和 `DISPATCH` 流水。运输从 [`Shipments`](../../../backend/src/main/java/com/homefulfillment/tms/Shipments.java) 进入。
3. 取消、拣货和出库必须先锁同一个订单头；换成各自锁履约或任务会允许「一仓开始拣，另一仓被取消」。签收后允许重放原事件，不允许新事件覆盖签收。

| 动哪一层 | 从哪看 |
|---|---|
| 老单没有任务 | [`V4` 的历史补任务](../../../backend/src/main/resources/db/migration/V4__outbound_and_transport.sql)，按预占状态映射，不调整历史余额。 |
| 第一次确认动作与重复动作 | `Fulfillments.pick()` / `OutboundCommands.dispatch()`；原请求键由 `CommandJournal` 保留状态码，换键只回既有事实，不再扣账。 |
| 运输迟到和重复 | `Shipments.addEvent()` 先锁运单、识别原事件，再检查事件时间与终态。 |
| 订单摘要显示不对 | [`OrderRead`](../../../backend/src/main/java/com/homefulfillment/fulfillment/OrderRead.java) 按事实算两个摘要，不要让 Vue 自己推导。 |

没有新依赖。读写及三角色权限仍复用已有会话和同一 MySQL。真实验收用 `tests/m1.py --m3`；SQL 入口为 [`verify-m3.sql`](../../../infra/mysql/verify-m3.sql)，改事务前先跑 A08/A09。

# 面试训练｜把事实讲得有分量

目标岗位：资深全栈 / 供应链业务系统开发。我们要练的是**讲清业务、技术取舍和个人贡献，在追问后仍站得住**，不是把本地实战编成生产经历。个人摸底、掌握等级和下一题只记在 [学习方案](learning.md)；工程通过情况只看 [TASK-v1](TASK-v1.md)。

## 现在怎么讲

当前代码到 M4 本机实战：双仓出库、模拟运输、真实 RocketMQ 与 Redis。**没有对接真实承运商、上线或生产压测**。可用的保守句子：

> 这是一个本地供应链实战项目。一张订单可以分两个仓，缺货时不留部分预占。确认出库才扣账，并在同一事务留下待发事件；Broker 停服不阻塞仓库出库。消息重复时，消费者用事件号去重，运单再按出库单唯一限制。验证用本机真实 Broker 与 MySQL，不说成生产结果。

上面是阶段描述，不预填个人贡献。模型实现与跑测不算个人贡献；只有你亲手做过、能复核的切片才能说「我负责实现」。练完 S1 后，可用「为什么上架不是第二次入库」展开一段业务故事，再用同请求键重试或事务回滚支撑工程追问。

## 素材怎么变成可用答案

用 **业务问题 → 我的范围 → 一个关键取舍 → 实现 → 验证 → 边界**，不要背几十个组件。

| 证据 | 需要记下 |
|---|---|
| 业务 | 一个能报出数字的矛盾：比如订10到8，为什么不能按已完成结单。 |
| 个人责任 | 哪个字段/页面/方法/测试自己写或改、哪个是 AI/前人提供，如何独立验证。 |
| 核心取舍 | 采用方案、放弃的方案及代价；用现有设计或代码证明，不把设计目标当测试结果。 |
| 复核 | 页面链接、单号、SQL、Java 方法、失败用例/真实输出；新仓有提交再记录短 SHA。 |
| 限制 | 本机、模拟渠道/承运商；没有压测就不说 QPS，没有上线就不说线上和生产。 |

不同长度讲法用同一组事实：

- **30 秒**：谁遇到什么问题、你具体负责哪一块、一个已经证实的结果。
- **1 分钟**：加「字段为何这么存」「哪个动作改变库存」「失败怎么验证」；只讲一个难点。
- **3 分钟**：画业务主线，展开写入事务和失败路径；讲一个真的发生过的问题和定位过程，再讲替代方案、何时需要改。没发生过的只能说「风险/设计演练」。
- **简历 bullet**：动作 + 方案 + 验证结果。示例结构是「实现了 X，使用 Y 解决 Z，以真实 MySQL 的异常/并发用例验证 W」；X/Y/W 尚无证据时不使用这条。

## 追问题库（提前公开，不默认考试）

| 题目 | 第二层追问 | 何时可以说“本项目已验证” |
|---|---|---|
| 采购订10收8，怎么查还欠多少？ | 最后2件遇到两个并发收货请求，谁失败？超时换键为什么危险？ | A02–A04 有证据，且你能自己读出回滚前后的表。 |
| 为什么要库存余额和流水？ | 上架总量没变，删掉一边流水会从哪里看出错？ | 有同 `putAwayNo` 的源负/目标正、余额和账实差异的例子。 |
| 两仓合计够，但同一笔订单第二个 SKU 不够呢？ | 哪把锁保住跨单竞争？SKU 粗粒度锁的代价？如何用真实 MySQL 反证？ | A05–A07 实跑；只做设计推演就直说。 |
| 为什么在出库时扣库，不在拣货扣？ | 已拣取消应该重加哪些货？现在为何禁止？双仓只发一个时谁更新哪个状态？ | A08–A10 或本人完成相关减法/并发测试。 |
| 为什么出库不等 MQ？ | 发布成功未标状态、消费成功未确认、人工补建撞上消费，分别会重做哪里？ | A11 有 outage/恢复和幂等证据，不只看 outbox `PUBLISHED`。 |
| Redis 和搜索为什么不在交易主链？ | 缓存过期或 Redis 挂时，页面、可售判断、恢复分别怎样？ | A12 对应行为实测；ES 不是 V1 功能。 |

## 模拟面试与验收

等用户说「开始模拟面试」再做。一次问一题，先让用户答，沿答案连续追问两层：**举证**（具体表/方法/测试）和**迁移**（条件变了怎么设计）。不替学员背题；指出一处证据缺口，回到一个 SQL 或方法，允许重讲。评分看业务是否准确、贡献是否可证、关键取舍是否解释、能否处理反例；不要按时长或术语多少判断。

结课交付：从已验收、本人能解释的切片选两条故事（一条业务建模，一条工程异常），各写 30 秒 / 1 分钟 / 3 分钟版本、两层追问题，以及能写进简历的事实。**当前未生成个人简历成绩，也没有承诺拿到 offer。**
